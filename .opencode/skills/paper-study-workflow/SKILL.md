# Paper Study Workflow（论文学习工作流）

## Overview

本工程是一个**个人具身智能算法学习仓库**，核心资产是"论文精读笔记 + 复现实验记录"，全部用中文 Markdown 维护。本 skill 定义学一篇新论文时**该动哪些文件、按什么规范写**，保证每次学习后仓库结构一致、索引最新。

**核心原则：一篇论文一次完整闭环** = 建档（目录+PDF+笔记骨架）→ 精读（按 11 节模板写满笔记）→ （可选）复现（code/ 下证据分栏的记录）→ 同步（根 README 三处索引）。不要只写一半或跳过 README 同步。

## When to Use

- 用户要**学一篇新论文**、把新论文加进仓库
- 用户**精读/总结某篇论文**，要求"按老规矩写笔记 / 更新笔记"
- 用户做了**复现实验**，要写实验记录或更新已有复现文档
- 用户要求**更新 README**（论文清单 / 学习路线 / 更新日志）
- 检查仓库结构一致性、为新论文排号

## 仓库结构地图

```
.
├── README.md                       ← 根索引：仓库结构 + 论文清单表 + 学习路线 + 更新日志
├── papers/
│   ├── _template/README.md         ← 笔记模板（唯一权威模板，新建笔记必须复制它）
│   └── NN-topic/                   ← 每篇论文一个序号目录，如 01-act
│       ├── <论文全名>.md            ← 精读笔记（按模板填写，中文）
│       └── <论文全名>.pdf           ← 论文 PDF（与笔记同名）
└── code/
    ├── README.md                   ← code/ 索引与实现路线说明
    ├── reproduction_<paper>.md     ← 复现实验记录（证据分栏纪律见下）
    ├── data/                       ← 数据集/checkpoint（gitignored，不入库）
    └── outputs/                    ← 实验产物（png/log/json/csv，入库）
```

## 端到端工作流

### Step A — 建档（新论文）

1. **确定序号**：取 `papers/` 现有最大编号 `NN` 的下一个（现有 `01-act` → 下一篇 `02-…`）。序号目录用 `NN-短主题词`，主题词用英文小写连字符（如 `02-diffusion-policy`）。
2. **复制模板**：把 `papers/_template/README.md` 复制为 `papers/NN-topic/<论文全名>.md`。论文全名 = 论文**英文官方标题**（与 PDF 文件名完全一致，含空格；这是仓库约定，别改成缩写或中文）。
3. **放 PDF**：同名 PDF 放入同一目录（`papers/NN-topic/<论文全名>.pdf`）。
4. 骨架完成后，若只是建档（尚未精读），根 README 论文清单中该行状态标 `📝 待读`；若边建档边精读，见 Step B。

### Step B — 精读笔记（11 节模板）

**先读一遍 `papers/_template/README.md` 与一篇已完成的范本（`papers/01-act/` 下的 ACT 笔记是黄金范本），照其结构与深度填写。** 模板里的 `<!-- … -->` 注释是写作指引，填充真实内容后**删除注释**。

各节要点（与范本核对）：

1. **标题 + 顶部引用块**：`# <论文全名>`，紧跟 `> **一句话总结：** …`（用三方向之一回答核心贡献：首次证明了什么 / 提出什么方法效果如何 / 在什么基准上超越谁）。
2. **§1 Paper Information**：标题/作者/发表（会议 年份）/链接（arXiv、Code、Project Page）。作者格式 `姓名 (机构)`。
3. **§2 Motivation**：`2.1 Background`（当前方法瓶颈，bullet 分条）、`2.2 Goal`（一句话研究问题，用引用块）、`2.3 核心洞察`（2–3 条设计哲学 bullet）。
4. **§3 Core Ideas**：核心贡献提炼成 3–4 个，标题用 `① … / ② … / ③ …` 编号，每条"一句话定位 + 为什么重要"。全文最重要的贡献排最前。
5. **§4 Overall Framework**：流程图/结构图**一律用 Mermaid**（` ```mermaid ` + `flowchart TD/LR`，必要时 `subgraph` 表达模块大框），至少含**数据流（Inference Path）**；如有训练/采集交替则加第二张图。图上方用文字标注数据规模、维度；长节点文本用双引号包裹、`<br/>` 换行。Mermaid 惯例与示例见模板 §4。
6. **§5 Key Modules**：每个核心模块 `### 5.x <名称>`，内部固定三段式 `#### Motivation` → `#### 核心思想` → `> **一句话总结：** …`。
7. **§6 Mathematical Formulation**：先 `### 符号说明`（表：符号/含义/维度），再分核心公式组（LaTeX `$$…$$`），每条公式给直观理解；Loss 汇总放最后（含各项含义）。
8. **§7 Training Pipeline**：伪代码用论文同款算法框（`─` 分隔线 + `Algorithm N: 名称` + 行号 1:…），随后接**超参数表**与**"论文写法 vs 代码实际"核对表**（读论文踩坑点，如论文误写、实现 bug、转述失真）。配复现时加 `> **🔁 对照复现**` 行指向复现文档对应小节。
9. **§8 Inference / Planning**：推理伪代码 + 与基线对比的成功率表 + 消融结论（每条给数字依据）。真实/仿真任务数字分清楚。
10. **§9 Limitations**：4–6 条，每条"具体局限 + 为什么是局限 +（可选）后作如何改进"。结尾一句承接到后续方向。
11. **§10 Relationship**：`### 历史脉络`（Mermaid flowchart：本文为根节点 → 前置/后续工作）、`### 承上`（与前作对比表，5–6 维度）、`### 启下`（4–5 条影响，结合具体工作）。
12. **§11 Personal Insights**：`这篇论文为什么重要？`、`最有启发性的设计`、`历史定位`（哪些已被超越/哪些至今有效/个人判断），最后 `> 一句话评价：…` 收尾。

**写作纪律：**
- 全文中文（术语/论文名/代码标识符保留英文）。
- **图的规范**：流程图/结构图（架构图、数据流、训练/采集流程、历史脉络树）统一用 Mermaid（` ```mermaid `）；节点文本含特殊符号（`（）→×+` 等）时用双引号包裹、多行用 `<br/>`，模块大框用 `subgraph`；方向按"整体纵向 TD / 左右关系 LR"选。**防坑：节点文本内禁止嵌套 ASCII 双引号 `"`（会把字符串截断、解析失败），需强调时用「」**。**算法伪代码框不是图**——§7 / §8 的 `Algorithm N` 保持 `─` 分隔代码块，不转 Mermaid。
- 涉及复现的结论标注 `> **🔁 对照复现**：…`，用相对路径链接 `code/reproduction_*.md`（从 `papers/NN-topic/` 出发为 `../../code/reproduction_*.md`），并说明与论文的差异（配置/规模/指标口径）。
- 链接一律相对路径；含空格文件名用 `%20` 转义（如 `papers/01-act/Learning%20Fine-Grained%20…md`）。
- 笔记写实，标注哪些是"论文说法/官方实现/本工程复现"三层信息，不混为一谈。

### Step C — 复现记录（做了实验才需要）

1. 文件：`code/reproduction_<paper>.md`，并在 `code/README.md` 结构图中登记 + 更新学习路径。
2. **证据分栏纪律**（照 ACT 复现文档结构）：开头的证据边界表按"训练稳定性 / 离线策略泛化 / 闭环工程链路"三类分栏，注明每类"能证明什么 / 不能证明什么"。
3. **永不虚构**：无实机就写"无实机成功率"；仿真/离线条目不得写成实机性能；无匹配仿真就说清证据止于离线指标。
4. 记录字段齐全：数据集 card、resolved config、checkpoint 结果表、per-dim/per-horizon、局限与"冻结口径"、产物清单。
5. 实验产物放 `code/outputs/<run>/`（png/log/json/csv 入库；**数据集/checkpoint/notebooks 不入库**——见根 `.gitignore`）。

### Step D — 同步根 README（每次闭环后必做）

改三处，全部用原文语言（中文）：

1. **仓库结构图**（如目录树有出入则更新）。
2. **论文清单表**：加一行 `| # | [论文全名](papers/NN-topic/<URL 编码名>.md) — 作者, 会议 年份 | 状态 |`；读完把状态改成 `✅ 已完成`（中途可 `🔍 阅读中`）。状态符号严格用 `📝 待读 / 🔍 阅读中 / ✅ 已完成`。
3. **学习路线**：勾掉已完成项 `- [x]`（含核心论文/动手实现），并在下方新增待办项（如对比算法、延伸方向）。新论文若属于既有路线项，勾选并在括号注明笔记位置。
4. **更新日志**：追加一行 `| YYYY-MM-DD | 干了什么（含文件链接）|`。日期用当天真实日期，格式与既有行一致。

## 不变式检查清单（收尾前逐项核对）

- [ ] `papers/` 编号连续无跳号、无重复；目录名 `NN-topic` 规范
- [ ] 笔记文件名 = PDF 文件名 = 论文官方标题
- [ ] 笔记按 11 节模板结构，无残留 `<!-- … -->` 注释、无 `[占位]`/`TODO`
- [ ] §1 链接真实（arXiv/Code/Project 至少给得出手的）
- [ ] 复现结论带 🔁 交叉引用，且路径指向真实存在的文件
- [ ] 根 README 三处（清单/路线/日志）已同步，状态符号正确
- [ ] 全文中文、术语一致；相对链接全部可解析（从仓库根用 `git ls-files` 或浏览器点一遍核对含空格路径的转义）
- [ ] git 只提交该入库的文件（`data/`、`notebooks/`、`.omo/` 在 `.gitignore` 中，勿 `git add -f`）

## Common Mistakes

| 错误 | 正确做法 |
|------|----------|
| 目录排号跳号或重复（如已有 01 就建 03） | 取最大编号 +1 |
| 笔记文件名用缩写/中文/`NN-topic.md` | 用论文官方英文标题全名，与 PDF 一致 |
| 模板注释不删，留下空的 11 节骨架就收工 | 精读要写满各节并删除 `<!-- -->` |
| 一句话总结缺失或写流程不写贡献 | 顶部引用块必须回答"核心贡献是什么" |
| 复现结论不标证据边界，把离线/仿真写成实机成功 | 三类证据分栏；无实机明说无实机 |
| 用 ASCII 手绘流程图/结构图（架构图、数据流、历史脉络树） | 用 Mermaid（` ```mermaid ` + `flowchart`），长文本双引号包裹、`<br/>` 换行；仅 §7/§8 算法伪代码框保留 ASCII |
| 读完不更新根 README | 论文清单 + 学习路线 + 更新日志三处一起同步 |
| 用绝对路径或未转义空格链接 | 仓库内一律相对路径，含空格用 `%20` |
| 把数据集/checkpoint/notebooks 提交进 git | 遵守 `.gitignore`（`data/`、`notebooks/`、`.omo/` 不入库） |
| 自己凭印象编模板结构 | 每次先读 `papers/_template/README.md` 与 `01-act` 范本 |

## 验证

- 笔记/复现文档写完后：把根 README 与论文清单中的每个 `.md`/图片链接在仓库内解析一遍；PDF 确实存在于对应目录。
- 若有跑得动的命令（如链接检查脚本），运行后确认零错误再报告完成；未引入的既有问题单独说明。
